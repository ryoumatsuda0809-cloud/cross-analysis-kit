# 公的法人データの叩き方とマッピング（Stage 1 補強）

> 目的：対象が「法人」のとき、公開情報スキャンの**同定と客観欄**を、Web検索より確実に固める。
> 使う順番は **同定 → 肉付け → 補完**。先に同定を確定させてから肉付けする（同名他社の取り違えを防ぐため）。

## 使う順番
1. **法人番号API（国税庁）で同定** … 13桁の法人番号を確定。同名多数を潰す決定打。
2. **gBizINFO（経産省/デジタル庁）で肉付け** … 設立・資本金・従業員・許認可・補助金・調達・財務を取得。
3. **Web検索で補完** … 建前（理念・採用）・口コミ・ニュースなどAPIに無いもの。

---

## 1. 法人番号API（国税庁）
- **用途**：会社の同定（→外形カードの「正式名称／法人番号／所在地」を確定）
- **料金**：無料
- **利用申請**：アプリケーションID（13桁）をメール申請。宛先 `invoice-web-api@nta.go.jp`、本文に「氏名又は名称・メールアドレス・法人番号Web-APIのみ利用希望」を記載。**発行に2週間〜1ヶ月**かかる。
- **ベース／仕様書**：https://www.houjin-bangou.nta.go.jp/webapi/ （仕様書PDF。最新Ver.4.0）
- **主な機能**：①法人番号指定 ②名称・所在地検索 ③期間指定（差分更新）
- **形式**：XML / CSV
- **叩き方の考え方**：`name=会社名` で候補を取得 → **所在地（例：{自治体}{町名}大字{字名}…）で1社に確定** → 13桁法人番号を得る。1社に絞れなければ憶測で決めず候補を列挙してユーザーに確認（Stage 1のエッジケース分岐と一致）。

| 取得項目 | 外形カードの欄 |
|---|---|
| 商号・名称 | 1. 正式名称 |
| 法人番号(13桁) | 1. 法人番号 |
| 所在地 | 1. 所在地 |

## 2. gBizINFO（経済産業省）
- **用途**：確定した法人番号で、外形カードの客観欄を一気に埋める
- **料金**：無料
- **利用申請**：Web API利用申請でAPIトークンを発行
- **認証**：リクエストヘッダーに `X-hojinInfo-api-token: {トークン}`
- **法人番号指定エンドポイント**：`GET https://info.gbiz.go.jp/hojin/v1/hojin/{法人番号}`
- **他のエンドポイント**：フリーワード検索／更新情報取得
- **形式**：JSON ／ 仕様(Swagger)：https://info.gbiz.go.jp/hojin/swagger-ui.html

| gBizINFOの主な項目 | 外形カードの欄 |
|---|---|
| 設立年月日 | 1. 設立・資本金 |
| 資本金 | 1. 設立・資本金 |
| 従業員数 | 1. 従業員規模 |
| 事業内容 | 1. 事業内容 |
| 許認可 | 1. 許認可・補助金 |
| 補助金 | 1. 許認可・補助金 |
| 調達（受注実績） | 参考：取引・実績の傍証 |
| 財務情報 | 3. 市場・競合（対象が公開している場合のみ） |

## 3. ★自治体の委員会資料（2026-08-04 追加｜最も収穫が大きい）

> **案件Aの実走で判明。** gBizINFO より濃い情報が、自治体サイトのPDFに落ちていた。
> 法人番号API・gBizINFO と**同格の必須ソース**として扱う。

### 対象になる法人

行政と契約関係にある法人。地方の中小企業では該当することが多い。

- **指定管理者**（公の施設の運営：道の駅・温泉・体育館・文化施設・駐車場など）
- 第三セクター
- 補助金・助成金の受給者
- 公共調達・入札の受注者
- 指定・認定を受けた事業者（介護・保育・産廃など）

### 探す順番

| # | 探すもの | 検索語の型 | 得られるもの |
|---|---|---|---|
| 1 | 選定結果の公表ページ | `{自治体} {施設名} 指定管理 選定結果` | 指定期間・候補者・添付PDF一覧 |
| 2 | **選定委員会 議事録** | 上記ページの「別紙2」等 | **★本命。** 委員の質問と経営者の回答が逐語で残る |
| 3 | 審査基準・配点 | 「別紙1」等 | 自治体が何を重視しているか |
| 4 | 事業計画書・収支計画書 | 「別紙3」等 | 収支構造（※スキャンPDFで機械可読でない場合あり） |
| 5 | モニタリング・評価シート | `{自治体} 指定管理者 モニタリング` | 年度ごとの実績評価 |
| 6 | 議会の会議録 | `{自治体} 議会 会議録 {施設名}` | 施設の課題が議員から指摘されている場合がある |

### 議事録から取れることがある項目（例）

| 項目 | 値 | 通常の入手可否 |
|---|---|---|
| 年間来店客数 | （実数・ローカル専用） | 非公開が普通 |
| 温泉利用者数 | （実数・ローカル専用） | 非公開が普通 |
| 経営状況 | 赤字・黒字への言及 | **非上場では基本入手不能** |
| 離職率 | （実数・ローカル専用） | 非公開が普通 |
| 会計の建て付け | 指定管理と自主事業の費用の分け方 | 非公開が普通 |
| 業務実態 | 使っているシステム・取れているデータ | 非公開が普通 |
| 経営者の課題認識 | 経営者自身の発言（課題として挙げたこと） | 非公開が普通 |

### 読み方の勘所

- **委員の質問と経営者の回答が噛み合っているか**を見る。噛み合っていない箇所は、
  経営者が「そこを課題と認識していない」サインであり、仮説の起点になる
- 数字には**但し書き**が付くことが多い（「来店客数のカウントになりますが」＝実人数ではない）。
  但し書きごと `01` に記録する
- 「按分」「区分経理」という言葉が出たら、**部門別採算が本当に見えているかを疑う**手がかり
- **議事録は「その人がそう述べた」という事実。** 内容の真偽は判定しない。
  `01` には「〜と述べている〔議事録〕」の形で書く

### 限界

- PDFが**スキャン画像**で機械可読でないことがある（実例：事業計画書2.65MBが読めなかった）
- 公募が非公募・随意契約だと委員会自体が開かれない
- 指定更新のタイミング（数年に一度）でしか更新されない。**情報が数年古い**可能性がある

### 探し方
- 各自治体の公式サイトで「指定管理候補者 選定結果」「選定委員会 議事録」を検索する

## 4. 注意（守秘・限界・段取り）
- **守秘**：これらは公開データのAPI。**機密の現場メモは絶対に送らない**（スキルの鉄則と同じ）。
- **中小・非上場は項目が薄い**（特に財務）。埋まらなければ「不明」と明記し、Web検索で補完する。憶測で埋めない。
- **申請に時間差**がある（特に国税庁は最大1ヶ月）。**それまではWeb検索で同等の同定・肉付けを行い、手法を先に確立**しておく（資料の方針「Web検索で確立→効くものだけMCP化」と一致）。
- **将来のMCP化**：ここが固まったら処理を `scripts/fetch_company_data.py` に逃がし、SKILL.md本文は「これを実行せよ」に変えるだけ。手順は不変のまま、精度と速度だけ上がる。
