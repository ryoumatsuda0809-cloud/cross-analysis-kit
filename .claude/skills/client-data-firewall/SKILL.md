# client-data-firewall ｜ 手法は共有し、顧客データは出さない

## なぜフォルダ除外だけでは足りないのか

2026-08-10 に実際に起きたこと（実走ログ 3-15・3-16）：

1. 顧客の診断結果が `案件/` 配下にあり、**git が追跡していた。既に push されていた**
2. `.gitignore` に `案件/` を足して止めた。**これで安全だと思った**
3. **確かめたら、まだ漏れていた。** 顧客の実数（来店客数・離職率・**法人番号**）が
   `STATUS.md` と業界パックとスキルの中に**コピーされていた**。そこは push 対象だった

> **`.gitignore` は「場所」で守る。だが数字は場所を移動する。**
> 引用され、要約され、「業界の知見」として手法側の文書に写る。フォルダ除外は素通りする。

そして最も重要なこと：

> **3-15 も 3-16 も、目視では見つからなかった。見つけたのは grep。**
> 人間の注意力に依存する層は、必ず破れる。

---

## 3層で守る

| 層 | 何で守るか | 止められるもの | 止められないもの |
|---|---|---|---|
| **1. 場所** | `.gitignore` | 案件フォルダ丸ごと | **手法側に書かれた顧客の数字** |
| **2. 内容** | コードネーム化＋退避 | 既に写ってしまった実名・実数 | **明日また書くとき** |
| **3. 機械検査** | pre-commit フック | 手が滑ったとき | 人が `--no-verify` で迂回したとき |

**3層とも要る。** 1と2は人間が正しく動くことが前提だから。

## 手順

### Stage 1 ｜ まず現状を測る（推測しない）

```bash
cd <リポジトリ>
git config core.quotepath off      # 日本語ファイル名がエスケープされるのを止める

# ① git が追跡している顧客データ
git ls-files | grep -E "^(案件|診断結果|clients|cases)/"

# ② 履歴に入っているか（＝push 済みなら GitHub にある）
git log --oneline --all -- '案件/**' '診断結果/**'

# ③ ★push 対象のファイルに顧客の固有情報が写っていないか
for f in $(git ls-files); do
  h=$(grep -nE "<実名>|<法人番号>|<電話番号>|<地名>|<特徴的な実数>" "$f" 2>/dev/null)
  [ -n "$h" ] && echo "--- $f" && echo "$h"
done
```

**③を飛ばさない。** ①だけ見て「案件フォルダを除外すれば終わり」と判断すると、3-16 を繰り返す。

> **法人番号・電話番号・住所は個社を一意に特定する。** 数字だから見落としやすいが、最も危険。

### Stage 2 ｜ 場所で守る（`.gitignore`）

```gitignore
# ══════════════════════════════════════════════
# push する = 手法（スキル・設計・憲法・実走ログ）
# push しない = 案件（顧客の診断結果）
# ══════════════════════════════════════════════
案件/
診断結果/
```

**フォルダごと除外する。** 「01〜03 は追跡して 04〜06 は除外」のような
細かい線引きをしない。**線が細いほど、次の人が跨ぐ。**

> 「private だから追跡してよい」は成立しない。**private は「漏れない」保証ではなく「漏れにくい」だけ。**
> 同期の都合で守秘を緩めない。同期は git 以外の手段で行う（案件は1台に固定する等）。

既に追跡されているものは追跡だけ外す：

```bash
git rm -r --cached 案件 診断結果    # ★--cached：ディスクのファイルは消えない
```

### Stage 3 ｜ 内容で守る（★削除ではなく「移す」）

**ローカルには顧客情報を全部置いてよい。GitHub に出さなければよい。**
だから**消さずに移す。知識を失わない。**

#### 3-1. 退避先を作る（`.gitignore` 済みの場所）

`案件/_社名対応表_ローカル専用.md` に、実名と実数を全部集める。

```markdown
| コードネーム | 実名 | 業種 | 状態 |
|---|---|---|---|
| 案件A | （実名） | （業種） | A軸のみ実走済み |
| 案件B | （実名） | （業種） | 検証専用・終了後に削除 |

## 案件A｜手法側から移した実数
| 項目 | 値 |
|---|---|
| 来店客数 | ◯◯万人 |
| 法人番号 | ◯◯◯◯ |
```

#### 3-2. push 側を置換する

```bash
python3 - <<'PY'
import subprocess, os
files=[f for f in subprocess.check_output(['git','ls-files'],text=True).split('\n')
       if f and os.path.isfile(f)]
subs=[('<実名>','案件A'), ('<法人番号>','（法人番号・ローカル専用）'),
      ('<地名>','{自治体}'), ('<実数>','（実数・ローカル専用）')]
for f in files:
    s=open(f,encoding='utf-8').read(); o=s
    for a,b in subs: s=s.replace(a,b)
    if s!=o: open(f,'w',encoding='utf-8').write(s); print("修正:",f)
PY
```

> **`perl -i` に `-CSD` を付けると日本語の置換文字列が文字化けする**（実際にやらかした）。
> `python3` で明示的に `encoding='utf-8'` を指定する方が安全。

#### 3-3. ★「やり方」は残し、「その会社の数字」だけ抜く

これが判断の勘所。

| 残す（＝手法） | 抜く（＝1社の事実） |
|---|---|
| ✅「従業員数と厚生年金被保険者数の差から社保適用外比率が推定できる」 | ❌「従業員34人／被保険者21人」 |
| ✅「指定管理者の議事録を当てろ」 | ❌ 来店客数・利用者数などの**実数** |
| ✅「DXの空白＝ツールが無い、と決めつけるな」 | ❌ 法人番号・電話・住所 |

> **1社の実数が「業界の一般論」の顔をして次の案件に配られる**のが最悪の事故。
> 実際に起きた（出典未検証の「◯◯41%」が業界パックから配られていた）。

### Stage 4 ｜ 機械検査（pre-commit フック）

**フック本体は commit される（＝公開される）ので、禁止語をフックに書かない。**
禁止語リストは `.gitignore` 済みのローカルファイルに置き、フックがそれを読む。

`.githooks/pre-commit`：

```sh
#!/bin/sh
NG=0

# 検査1｜案件・診断結果が混ざっていないか
# ★--diff-filter=d ＝ 削除は除く。追跡解除（git rm --cached）のコミットは通す必要がある
BAD=$(git diff --cached --name-only --diff-filter=d | grep -E '^(案件|診断結果)/')
[ -n "$BAD" ] && { echo "✋ 顧客の診断結果が含まれています"; echo "$BAD"; NG=1; }

# 検査2｜追加行に禁止語が無いか
LIST="案件/_禁止語_ローカル専用.txt"
if [ -f "$LIST" ]; then
  HITS=$(git diff --cached -U0 | grep '^+' | grep -v '^+++' | grep -F -f "$LIST" | head -20)
  [ -n "$HITS" ] && { echo "✋ 禁止語が含まれています"; echo "$HITS"; NG=1; }
else
  echo "⚠️  $LIST が無いため、禁止語チェックを飛ばしました"
fi

[ "$NG" = "1" ] && { echo "意図的に通す場合のみ： git commit --no-verify"; exit 1; }
exit 0
```

有効化（**1台につき1回**。clone した別マシンでも必要）：

```bash
git config core.hooksPath .githooks
chmod +x .githooks/pre-commit
```

### Stage 5 ｜ ★フックをテストする

**ガードレールもテストしないと動かない。** 初版のフックは
「追跡解除コミット自体をブロックする」欠陥があった（削除も `案件/` パスとして検出されたため）。

```bash
# テストA：新しい案件は自動で除外されるか
for p in "案件/新しい会社/03.md" "診断結果/x.md" "案件/x/_材料/B_現場/メモ.md"; do
  git check-ignore -q "$p" && echo "✅ 除外 $p" || echo "★漏れ $p"
done

# テストB：クリーンな状態で commit が通るか（＝誤検知しないか）
sh .githooks/pre-commit && echo "✅ 通った"

# テストC：禁止語リストが実際にヒットするか
echo "<実名を含む行>" | grep -F -f 案件/_禁止語_ローカル専用.txt && echo "✅ 効いている"
```

## ★既に push 済みだった場合

**`.gitignore` は過去の commit を消さない。** 履歴にも GitHub にも残っている。

| | やること | 向いている状況 |
|---|---|---|
| **A. 履歴を書き換える** | `git filter-repo` / BFG で該当パスを全履歴から削除 → **force push** | 履歴（判断の経緯）を残したい |
| **B. リポジトリを作り直す** | 作業ツリーから手法だけで新規リポジトリを作り、旧を削除 | **commit 数が少ない**（数十程度） |
| C. 何もしない | private かつ単独利用と割り切る | **推奨しない** |

**どれを選んだかを記録する。** 未決のまま放置すると、次の人が「対処済み」と誤解する。

## 判断に迷ったときの原則

- **守秘と利便を天秤にかけない。** 「同期しないと不便だから追跡する」は、
  一度そう決めると理由が独り歩きする。守秘を優先し、利便は別手段で解く
- **目視を信用しない。** 3-15 も 3-16 も grep で見つけた。人の目は必ず漏らす
- **線は太く引く。** 細かい例外を作るほど、次の人が跨ぐ
- **消すより移す。** ローカルには全部置いてよい。知識を捨てる必要はない
- **`--no-verify` で迂回したら、理由を記録に残す**

## 新しい案件を始めるときの確認

- [ ] 案件フォルダは `.gitignore` されている場所にあるか（`git check-ignore` で確認）
- [ ] 対応表にコードネームを登録したか
- [ ] 禁止語リストに実名・法人番号・電話番号を追加したか
- [ ] このマシンで `core.hooksPath` を設定済みか
