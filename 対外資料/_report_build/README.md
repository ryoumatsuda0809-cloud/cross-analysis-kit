# レポートPDFの工房

> **ここは「表（おもて）」を作る場所。**相手の手に渡る紙だけを扱う。
> **何回作っても同じ結果にする**ことが、この場所の目的。
> それを担保しているのは手順ではなく、**`build.sh` と `check_report.py`**。

---

## 使い方

```bash
cd 対外資料/_report_build
./build.sh ../デモ_20260919/見本_課題仮説レポート.md
```

**検査に通らなければ PDF は作られません。**（`check_report.py` が先に走る）

出力名を変えるとき：

```bash
./build.sh ../../案件/案件D/06_課題仮説レポート.md {事務所名}_課題仮説レポート_案件D.pdf
```

---

## どこを触るか（★ここを守ると、毎回同じになる）

| 触るもの | 何が決まるか |
|---|---|
| **`style.css`** | **体裁のすべて。**色・字体・余白・罫線・行間。**ここ以外に体裁を書かない** |
| レポートの `.md` | **中身だけ。**体裁は1行も書かない |
| `check_report.py` | 検査の項目。**仕様が変わったらここも直す** |
| `build.sh` | 変換の手順。基本は触らない |

> **★md と CSS を混ぜない。**中身を直したら `./build.sh` を打つだけで済む形を保つ。
> これが崩れると「前回と同じにならない」が始まる。

---

## 検査の中身（`check_report.py`）

| 見るもの | なぜ |
|---|---|
| **必須節が落ちていないか** | **2026-09-19 に、業際を守るための節を丸ごと落とした**（実走ログ 16-1）。<br>古い `06` を土台にすると、後から足した必須節が静かに消える |
| 内部語・HTMLコメントが残っていないか | 「実態」「自己申告」「棄却」「封」「内部メモ」等。提出物に出してはいけない |
| **誠実さの宣言**が入っていないか | 「正直に書きます」「隠さずに」。**AIっぽさの最大の原因**（実走ログ 16-2） |
| `{本人が書く欄}` が埋まっているか | WARN で出る。埋めずに出さない |
| 分量 | A4 4〜6ページの目安を超えたら WARN |

**逆テスト済み**：必須節を1つ消すと NG を返し、`build.sh` が PDF を作らずに止まる。

## 磨くときの手順

1. `.md` の中身を直す（言葉・構成）
2. `style.css` を直す（見た目）
3. `./build.sh` を打つ
4. **PDF を開いて、目で見る**
5. 直すところがあれば 1 か 2 に戻る

**見た目の反復は VS Code が速い。**CSS を1行変えて、`build.sh` を打ち直すだけ。
Cowork だと PDF → PNG → 目視で1往復が遅い。
